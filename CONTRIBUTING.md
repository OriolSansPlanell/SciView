# Contributing to SciView

Thank you for helping. Bug reports, templates, documentation and new object types are all welcome.

## Reporting a problem

Open an issue with:

* what you did, what you expected and what happened;
* the report zip from the editor's help (<kbd>?</kbd> > Save a report for a bug) or from
  `sciview info --report film.sciview.json`, which holds the film, its problems and the versions you use.

## Setting up for development

```bash
git clone https://github.com/OriolSansPlanell/SciView
cd SciView
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -e ".[test]"
pytest -m "not gui"
```

The editor test drives a real browser:

```bash
pip install playwright && playwright install chromium
pytest -m gui
```

Run `sciview edit` from the repository to try your changes; the editor's files are served straight from
`src/sciview/gui`, so reloading the page picks up JavaScript and CSS edits.

## Where things live

| Path | Contents |
| --- | --- |
| `src/sciview/engine/` | camera, canvas and drawing primitives, text, colours, assets, safe expressions |
| `src/sciview/model/` | property schema and keyframes (`base.py`), object types (`objects3d.py`, `objects2d.py`, `charts.py`), project files (`project.py`) |
| `src/sciview/render.py` | frame composition |
| `src/sciview/export.py` | parallel rendering and ffmpeg |
| `src/sciview/server.py` | the editor's local web server |
| `src/sciview/gui/` | the editor (plain HTML, CSS and JavaScript modules, no build step) |
| `src/sciview/templates/` | templates, generated by `tools/build_templates.py` |
| `docs/` | documentation; `docs/objects.md` and `docs/schema/sciview-1.json` are generated by `tools/gen_docs.py` |
| `tests/golden/` | template files from every release (they must keep opening) and reference frames |

## Adding an object type

1. Write a `SceneObject` subclass with `TYPE`, `LABEL`, `ICON`, `CATEGORY`, `DESCRIPTION`, a `PROPS` list and
   a `draw(cv, ctx, v, st)` method that returns the bounding box in output pixels (see
   [Plugins](docs/plugins.md#writing-an-object-type)). Types that do not belong in SciView itself can be a
   plugin instead: `sciview plugin new NAME`.
2. Decorate it with `@register` and import its module in `src/sciview/model/__init__.py`.
3. If it needs a new icon, add it to `src/sciview/gui/js/icons.js` (24 x 24, stroke icons).
4. Add it to `full_scene()` in `tests/test_render.py`, run `python tools/gen_docs.py` (reference and schema)
   and add a line to `CHANGELOG.md`.

## Changing how things look, or the file format

* A change meant to alter the picture fails `tests/test_visual.py`. Regenerate the reference frames with
  `python tools/update_golden_frames.py`, look at them, and commit them with the change.
* Additions to the file format need nothing special: older files keep opening. A change that is not additive
  needs a migration in `src/sciview/model/migrate.py` and a test with a file in the old form (see
  [Stability](docs/stability.md)).

Property names must not be `start`, `end`, `enter`, `exit`, `id` or `name` (they are timing fields).

## Style

* Python: readable over clever, type hints on public functions, `ruff check src tests` clean.
* Interface text: plain verbs, sentence case, say what happens ("Export video", not "Submit").
* Keep rendering a pure function of time: no state carried between frames.

## Pull requests

Keep them focused, include a test for behaviour changes, and describe what changed and why. By contributing
you agree that your work is released under the MIT licence.

Everyone taking part is expected to follow the [code of conduct](CODE_OF_CONDUCT.md).
